# Legacy review privacy — P1-03

This is an intentional product change from the historical M0 review workflows. The expanded Phase 1 direction removes public star ratings and organizer comment aggregates. Original `reviews` rows remain intact for their authors and active administrators. Moderation decisions in `moderation_reviews` are a separate feature and retain their authorization.

Migration `20260929021309_m1_legacy_reviews_private_history.sql` revokes anonymous privileges and authenticated INSERT/UPDATE/DELETE on `reviews`. Its sole SELECT policy admits the row author or an active administrator from the database profile. Event creation, club ownership and organizer membership confer no review access. A feature switch cannot change these database permissions. Operational deletion requests require the existing privileged process; there is no client deletion endpoint for historical rows.

`GET /api/events/:id/reviews` now returns `{ reviews: [...] }` with `private, no-store`, only after active-user authorization. Nonadmins receive an explicit `user_id` predicate as well as RLS. Admin history is limited to the requested event. Pagination is bounded to 100 rows with deterministic created-at/id ordering. The response has no public aggregate or write-eligibility fields. The legacy POST retains its authentication/ban/onboarding guards and then returns 404; the separate future feedback flag cannot reopen it.

The event UI has no review submission form, public average, rating distribution, stars or organizer comments. A signed-in author can view their own historical rating/comment; an active admin can inspect the event's history. The history cache key includes user ID to avoid carrying one account's data into another session.

Source audit covered the baseline and all forward migrations, public SQL functions/views/triggers, event/club analytics, event detail presentation and typed contracts. No public aggregate view, review trigger, review RPC, duplicated event rating column or club analytics review projection exists in this baseline. The legacy review API and `reviews` table were the aggregate/raw exposures; both are closed by this change. Elevated service-role fixtures remain privileged setup, not proof of caller access.

Regression coverage preserves the old test locations but explicitly replaces their former public-aggregate/write expectations. SQL suite `110-legacy-review-privacy.test.sql` exercises actual anonymous/authenticated roles, author/outsider/organizer/admin controls, banned admin, immutable writes and preserved original contents. The all-table RLS matrix also asserts the new boundary. Browser participation workflows retain author history, deny organizer/outsider access and prove retired submissions cannot write.
