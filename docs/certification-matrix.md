# Endpoint authorization and page smoke certification

The M0 matrix checks every live App Router endpoint and page against the checked-in audit inventory. `e2e/helpers/certificationInventory.ts` fails on an unclassified source file, HTTP verb, persona, page, or undeclared removal. The three removed debug/cron routes are explicit exceptions that must remain absent.

`e2e/specs/authorization-matrix.spec.ts` covers all 118 verbs across 91 live endpoint paths. Its thirteen persona columns include ten real seeded authenticated sessions, anonymous and unauthenticated machine requests, and the non-McGill OAuth admission case. Non-McGill endpoint cells are explicitly skipped: this is an OAuth admission contract, not a seeded authenticated identity. The callback unit tests exercise rejection without manufacturing an invalid admitted account.

GET expectations come from the reviewed inventory, with explicit source-reviewed corrections in `e2e/helpers/authorizationProbes.ts`. Mutation expectations are separately enumerated for every verb. Most requests use malformed JSON, readable forms without files, absent target identifiers, or self-follow rejection. These prove authorization and validation boundaries; they do not prove every successful workflow.

The remaining allowed mutation cells use `e2e/helpers/isolatedProbes.ts`: single-event popularity computation uses a disposable event; club-follow creation uses a disposable club; audit-writing deletes use absent random target IDs and remove only those audit rows. Authenticated sign-out uses a new auth user with the persona's gate properties, then verifies cookie removal and refresh-token revocation before deleting that user. A second session for an existing persona would be unsafe because global sign-out can revoke sibling sessions. All fixture cleanup runs in `finally`.

The batch scoring route has no narrow mode. Its local probe snapshots and restores both score tables with paginated reads, and restores any changed inferred tags. An inferred-tag restoration can advance that profile's `updated_at` via its ordinary database trigger. This test requires the harness's single worker and a reset local fixture database; it is not a concurrency-safe production restoration mechanism. Fixture clients explicitly reject nonlocal targets before creating a service-role client. The API matrix now has 1,416 runnable cells and only the 118 OAuth admission cells skipped.

All executed mutation/error responses must be `private, no-store`. Ban denials also assert their exact error body. Admin health is checked against its documented body/status relationship, since a degraded dependency legitimately returns 503. `health-machine.spec.ts` separately checks absent, wrong, short, and valid bearer credentials. Playwright forcibly supplies a known local-only test credential so Next cannot inherit a production monitor token from an environment file. Invalid credentials retain the anonymous liveness response. No status is learned from the observed response.

`e2e/specs/page-smoke-matrix.spec.ts` classifies all 43 pages, with 86 runnable cases. Each gets an anonymous visit and an explicitly chosen authenticated persona. It checks the expected path and, for proxy sign-in redirects, the exact `signin` and `next` query values. Readiness uses visible main content and dynamic fixture text, followed by completion of initial data requests already in flight; polling and realtime connections do not require global network idleness. Browser console errors and unhandled page exceptions fail the smoke. Dynamic paths use seeded identifiers. The missing invitation deliberately checks its error state. The experiment detail page creates a disposable draft with two variants, exercises the hydrated page, and removes the fixture in `finally`.

Local runs explicitly blank `VERCEL`; the product renders Vercel analytics widgets only on a Vercel deployment, where their script endpoints exist. `/docs` alone gets a CSP override for Redoc's blob search worker and exact attribution-logo URL. The installed Next header resolver test proves replacement of the base CSP rather than two conflicting policy headers; other pages retain the original policy.

CERT-18's bounded local outage/recovery exercise is `src/__tests__/api/m0-local-chaos.test.ts`: the real Supabase query client and real discovery handlers run against an injected failing fetch transport, then the same client recovers. It proves private 500 responses, retained error capture, no upstream detail leakage, and restoration of public successful reads without restarting a service. SDK retry delays are disabled for this deterministic test; retry timing and a real regional service outage are not claimed. Existing health and rate-limit tests separately cover unhealthy dependency reports and Redis fallback.

Run the browser tests against the local, seeded Playwright stack using the existing project setup. Listing or statically validating the matrix does not certify its runtime results. Successful workflow coverage, the external OAuth admission case, and every explicit skipped cell must remain separate in certification reporting.
