<objective>
Wave 1, independent tributary: pin the auth callback's current behaviour with tests written against unmodified source, so that every later phase that touches sign-in has a contract it can be measured against.

Purpose: REFAC-08 is not a testing task, it is an ordering obligation. The requirement says "characterization tests **before** it is modified", and the route in question carries McGill email enforcement — a constraint PROJECT.md § Constraints names as non-negotiable — plus admin auto-assignment, profile upsert and onboarding routing. Phases 5 and 6 will rewrite the authorization ring around it. If the contract is written after the first edit, it records whatever the edit produced rather than what shipped.

This plan also answers a specific criticism the program has already levelled at itself. `02-REVIEW.md` WR-04 found that `src/proxy.test.ts` asserts only `config.matcher`, so deleting the redirect block leaves the suite green — "a PRESERVE suite whose assertions cannot fail when the preserved behavior is removed is a false sense of coverage." Every assertion here calls the exported `GET` and asserts on the returned `NextResponse`, and task 2 proves mechanically that each one goes red when its branch is removed.

Output: the characterization suite, a recorded red per characterized branch, proof the route file is untouched, and a note recording the PRESERVE/DEFECT tagging and the two facts about production that make one of these tests describe a path that does not currently fire.

**No CONTEXT.md exists for this phase.** The binding decision for this plan is D-08: the four already-green probes in 03-RESEARCH.md § Code Examples 13 become the characterization suite, and its mock seams are `@supabase/ssr`, `@supabase/supabase-js` and `@/lib/supabase/service` — **not** `@/lib/supabase/server`, which the route does not import.
</objective>

| Boundary | Description |

| OAuth provider → auth callback route | The only place an external identity becomes an application session; McGill enforcement lives here |
| auth callback → service-role client | The route builds a service-role client inline and uses `auth.admin.deleteUser` on the rejection path — an RLS-bypassing credential on an anonymous-reachable route |
| environment variable → authorization decision | `ADMIN_EMAILS` is parsed at module load and grants the admin role; its value is a privilege decision made by configuration |
| test process → production source | A characterization plan creates pressure to edit the subject so assertions pass |
| agent runtime → production Postgres (MCP `execute_sql`) | Registered per AR-12 even though this plan issues no production read |
| laptop `.env.local` → production Postgres | Registered per AR-12; `SUPABASE_SERVICE_ROLE_KEY` on disk bypasses RLS |
