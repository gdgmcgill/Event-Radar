<objective>
Wave 2, the critical path, alone: turn a migrations folder that cannot replay into one that replays cleanly and produces production's schema — without renaming a single file.

Purpose: this is the hard problem the whole phase queues behind. The repository and production do not disagree at the margin; they describe two different databases. Production reports 45 applied versions. The folder holds 44 files that collapse to 39 distinct versions because of four collision groups covering nine files. The two sets overlap in only 27 versions. Eighteen versions are applied in production with no file in the repository. Twelve local files were never applied. One file does not parse as a migration filename and the CLI skips it with exit status 0 — silently. And `supabase db reset` aborts at the twelfth of 44 files on a duplicate primary key, which is also why `supabase db diff` was unusable in Phase 1: it builds its shadow by replaying exactly these files.

Nothing downstream runs until a reset completes. The type-drift gate, the pgTAP suites, the seed and the Playwright harness all need a local database built from the folder.

REFAC-01 forbids renaming, and the resolution is that the collisions stop being *migrations* without being *renamed*: all 44 files move, byte-identical and name-identical, into an archive subdirectory the CLI never reads. Then one baseline migration captures production's schema as real DDL.

Output: the archive as 44 pure renames in its own commit, a baseline reviewed against four named findings and against the live policy census by count and by name, a green `db reset`, an empty `db diff`, the filename check wired into CI now that it passes, and a reconciliation note recording what production still holds that the repository does not control.

**No CONTEXT.md exists for this phase.** The binding decision here is D-01: migration reconciliation is baseline-by-archive; all 44 existing files move by pure rename into an archive directory, then the baseline is pulled from production over a read-only-verified transport. Renumbering is forbidden. D-02 governs the production history repair, which this plan does not perform.
</objective>

<slice_outcome>
This plan is green when `supabase db reset` exits 0 with no skipped file **and** `supabase db diff --linked --schema public,storage` writes an empty file. Those two commands together are REFAC-01's success criterion, and neither has ever succeeded on this tree before.
</slice_outcome>
