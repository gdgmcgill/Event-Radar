<objective>
Wave 1, independent tributary: build the `src/server/` seam kit that Phases 4, 5 and 6 will refactor every route into, prove it with unit tests, and install the build-time boundary that stops a new route reaching the service-role client without review — while applying it to exactly zero routes.

Purpose: REFAC-05 asks for two things that sound contradictory and are not. It wants an import-boundary rule that *fails the build*, and it wants the seam applied to *zero* routes. Both are true at once only if the rule ships with a generated allow-list of the existing callsites that may only shrink. Without it, `npm run lint` goes from 0 errors to 46, and `check-baseline.mjs`'s `zero-eslint-errors` rule fails the phase gate — the research measured exactly this, in four configurations, on this tree.

The seam matters more than its size suggests. It is the only place in the program where "authorization happens here, fails closed, and reads the authenticated user rather than a session" becomes a shape rather than a convention. Every guard returns a discriminated result instead of throwing, so Phase 4's slices adopt it without changing control flow.

Output: seven source modules under `src/server/`, seven unit suites, an ESLint boundary proven to fire by a fixture, a generated shrink-only ratchet, a ratchet checker, the callsite census, and a note recording what the rule cannot catch.

**No CONTEXT.md exists for this phase.** The binding decisions here are D-05 (the escaped-bracket allow-list ratchet; the seam applied to zero routes; the service-client importer count under `src/app/**` does not move) and D-09 (`requireClubRole` generalizes the DELETE-handler shape over a required-role set and reports the actual role; admin is not a club-role bypass).
</objective>
