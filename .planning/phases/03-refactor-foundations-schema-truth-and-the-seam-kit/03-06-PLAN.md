<objective>
Wave 4: make the generated Supabase types a product of the reconciled schema, put a gate on them that fails when they drift, and remove every cast that lets code escape those types — without fixing the two real bugs the casts were hiding.

Purpose: the audit disproved the premise most people would start from. `src/lib/supabase/types.ts` is not hand-written — it opens with a header only the generator emits — and the drift analysis found zero type-mismatch rows across 288 reconciled rows. The file describes production faithfully. What it describes is a schema no migration could build, which is why regenerating it before plan 03-04 would have *hidden* drift rather than revealed it. Now that the migrations produce production's schema, regeneration is meaningful and a gate on it is worth having.

The gate's direction is the load-bearing decision. Generating from production would pass on day one and prove nothing forever. Generating from the local database built by the migrations fails the moment a migration and the committed types disagree, which is the property REFAC-04 actually wants — and it needs no production credential, which is a real security property rather than a convenience.

The cast clause turned out to be a day rather than a week, because the research measured it instead of estimating: removing all 47 casts produces exactly nine type errors across five files. Seven are noise. Two are genuine latent defects the casts were concealing, and this plan characterizes and registers them rather than fixing them, because a behaviour fix smuggled inside a type change is exactly what the program's own characterize-first rule exists to prevent.

Output: regenerated types, a CI job proven to fail on injected drift, zero casts, nine errors triaged and seven fixed properly, two DEFECT tests against newly registered findings, and a note recording each decision per site.

**No CONTEXT.md exists for this phase.** The binding decisions here are D-04 (the gate generates from the local database, never the linked project, and must be proven to fail on an injected drift before it is trusted) and D-10 (the 47 casts go to zero in one slice; the two latent defects get a characterization test each and are named in the summary rather than fixed).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migrations → generated types → every tier | The types are consumed everywhere; if they stop describing the schema, every consumer is wrong in the same way |
| pull request → merge | The drift job is the mechanical control between a schema change with stale types and the default branch |
| a cast → the type system | A client cast erases the whole client type including argument types, so it hides errors rather than resolving them |
| an unchecked awaited shape → the rendering page | An asserted promise shape means whatever arrives is trusted |
| agent runtime → production Postgres (MCP `execute_sql`) | The privileged transport; registered per AR-12 |
