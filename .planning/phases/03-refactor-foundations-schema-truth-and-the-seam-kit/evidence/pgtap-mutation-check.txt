# WHAT PRODUCED THIS FILE
#
#   $ bash scripts/pgtap-mutation-check.sh
#
#   The harness comments out each CREATE POLICY statement in
#   supabase/migrations/20260915230000_fk_indexes_and_policy_gaps.sql in turn,
#   rebuilds the local database from the folder, runs `supabase test db --local`
#   and requires a FAILURE; then restores the file with `git checkout --`,
#   rebuilds again and requires a PASS. Three policies, two rounds each, six
#   `supabase db reset --local` runs in total. Nothing touches production: every
#   command carries `--local` explicitly, and the harness reads no credential.
#
# WHY IT EXISTS
#
#   02-REVIEW.md finding WR-04 caught a Phase 2 suite whose assertions could not
#   fail when the behaviour they preserved was removed. The pgTAP equivalent is
#   worse, because RLS denial has two shapes — a raised error and a silent
#   zero-row filter — and the obvious assertion notices only one of them. A
#   green suite is therefore not evidence that the policies work. This file is.
#
# HOW TO READ THE KEY=VALUE LINES
#
#   mutation_lines_commented   how many lines of the policy's CREATE statement
#                              were commented out — a zero here would mean the
#                              matcher missed and the round proved nothing
#   removed_exit_code          `supabase test db --local` with the policy gone
#   removed_verdict            RED_ASSERTION       the suite failed by asserting
#                              RED_NOT_AN_ASSERTION  it failed to parse or run,
#                                                  which proves nothing
#                              GREEN               the suite passed without the
#                                                  policy — a decorative test
#   restore_clean              `git status --porcelain` on the migration after
#                              the restore; false means a mutation survived
#   restored_exit_code         the suite with the policy back in place
#
#   The run is only a proof when every policy records RED_ASSERTION followed by
#   restored_verdict=GREEN, and `failures=0` at the end.
#
# The reset and pg_prove transcripts are read by the harness but not reproduced
# here; only the derived verdicts and the named failing assertions are printed,
# so this file stays readable. The green transcript lives in
# evidence/pgtap-run.txt and the reset transcript in
# evidence/db-reset.after-fixes.txt.
#
# No credential, token, key or project reference appears below. Absolute paths
# are pg_prove's own output and are left verbatim, as in the phase's other
# captures.
