================================================================================
CLI VERSION PINNING — WHY THE CI JOB NAMES A VERSION
================================================================================

The generator's output is not stable across CLI versions. Measured:

$ npx --yes supabase@2.117.0 gen types typescript --local --schema public > /tmp/types.v2117.ts
$ diff -q /tmp/types.gen.ts /tmp/types.v2117.ts
Files /tmp/types.gen.ts and /tmp/types.v2117.ts differ

The difference is cosmetic — postgres-meta v0.99.0 parenthesises four generic
constraints that v0.98.0 leaves bare:

-  TableName extends DefaultSchemaTableNameOrOptions extends {
+  TableName extends (DefaultSchemaTableNameOrOptions extends {
     schema: keyof DatabaseWithoutInternals
   }
     ? keyof (DatabaseWithoutInternals[...]["Tables"] & ...["Views"])
-    : never = never,
+    : never) = never,

Cosmetic or not, a drift gate that diffs byte-for-byte would go red on a CLI
upgrade it did not ask for. The CI job therefore pins `version: 2.115.0` on
supabase/setup-cli, matching the CLI that produced the committed file. A CLI
bump becomes a deliberate, reviewable commit that regenerates the file, which
is the correct shape for this control.
