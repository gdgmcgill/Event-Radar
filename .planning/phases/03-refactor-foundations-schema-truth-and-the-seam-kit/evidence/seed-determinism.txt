# seed-determinism.txt — REFAC-07 clauses 1-3, proven rather than described
# Plan: 03-07 · Phase: 03-refactor-foundations-schema-truth-and-the-seam-kit · Recorded: 2026-09-16
#
# METHOD. Reset the local database from the migrations, load the seed, take a
# canonical dump, load the seed a SECOND time into the same database without
# resetting in between, take a second dump, and require the two to be byte
# identical. That proves both things at once: determinism (same inputs, same
# rows) and idempotence (the loader is re-runnable and the second run leaves
# the database in the same state as the first).
#
# THE DUMP. Produced by the loader's own --dump mode, which selects the seeded
# rows by their fixed ids, names every column explicitly so the output cannot
# drift with column order, and sorts by id. It includes the trigger-maintained
# users.saved_events_count and every created_at/updated_at, because a proof
# that skipped the columns a trigger can move would not be proving much.
#
# WHAT IS NOT DUMPED, AND WHY. The auth schema. GoTrue stamps its own
# created_at on every account it creates and those instants are not ours to
# pin. What this seed fixes about auth is the SET of account ids and their
# addresses, and that set IS in the dump under auth_identities.

# 4. The skip branch, at the TAP tier where it is visible.
#
#    `supabase test db` prints the pg_prove summary only, so "ok" above does
#    not distinguish an assertion from a skip. Running the file straight
#    through psql shows the difference. pgTAP is created first because
#    000-setup.sql is what normally does that, and it is not running here.
# ---------------------------------------------------------------------------

$ docker exec -i supabase_db_Event-Radar psql -U postgres -d postgres -Xq \
    -c "create extension if not exists pgtap with schema extensions;"
$ docker exec -i ... psql -Xqt -f - < supabase/tests/database/040-seed-coverage.test.sql

## 4a. Seed LOADED — the assertions execute.
     1..21
    
     ok 1 - seed covers role: user
    
    ...
ok=21 skip=0 not_ok=0

## 4b. Sentinel row removed — every assertion SKIPs, with its reason, and
##     the file still exits clean. This is what the type-drift CI job sees.
     1..21
    
     ok 1 # SKIP seed not loaded — run `npx tsx scripts/seed/load.ts` after `supabase db reset`
    
    ...
ok=21 skip=21 not_ok=0

# The two runs report the same 21 results and the same clean exit. The
# difference — 0 skips versus 21 skips — is the whole point: a green 040 in
# a job that did not load the seed is a green SKIP, and it says so in its
# own output rather than leaving a reader to assume.
