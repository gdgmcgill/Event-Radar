3. WHAT THIS STACK DOES AND DOES NOT CONTAIN
================================================================================

`"linked_project": null` — this stack is NOT linked to the production project. Nothing in
this plan ran `supabase link`, and no `supabase/.temp/` directory was created (03-RESEARCH.md
§ Pitfall 10). Every value above addresses 127.0.0.1.

The `public` schema is EMPTY and `supabase_migrations.schema_migrations` has no rows. The
migration replay was deliberately skipped — see `evidence/ports-preflight.txt` § 5 and § 6
for the failed first attempt (F-043's duplicate `(version)=(011)` abort, plus F-047's silent
`008b` skip) and for exactly how the stack was brought up without touching a migration file.
Plan 03-04 populates `public` from the baseline via `supabase db reset`.

`supabase_imgproxy_Event-Radar` and `supabase_pooler_Event-Radar` are stopped. Neither binds
a port declared in `config.toml`; no Phase 3 requirement uses Storage image transforms or
the transaction pooler.
