## 1. The fixes

calculate-popularity (both verbs): the inline service-key client factory, the
`@supabase/supabase-js` import and both machine-key gates are deleted. Each verb opens with
`createRequestContext()`, `requireActiveUser(ctx)`, `requireRole(ctx, "admin")` (the DEC-58
preamble every other admin arm uses) and then runs on `getElevatedClient()`. The rpc call's two
`as never` casts are removed: the generated types carry
`update_event_popularity: { Args: { p_event_id: string }; Returns: undefined }`, and tsc exits 0.
Success and error bodies are otherwise byte-identical. GET's unused request parameter is renamed
`_request` (the arm table calls `GET(r)` typed against the handler, so the parameter stays).

admin/users/[id] PATCH: `updateData` is `TablesUpdate<"users">`. With `roles` in the body, every
value must be a `user_role` enum member (read from the generated `Constants`), else
400 {"error":"Invalid role","field":"roles"}; a roles change on `auth.user.id` is
403 {"error":"You cannot change your own roles"}; `admin` is no longer stripped; `user` is still
added when absent. The update runs on `getElevatedClient()`. `{ user: data }` and the 500
{"error":"Internal server error"} bytes are unchanged. After a successful roles change,
`logAdminAction({ adminUserId, action: "updated", targetType: "user", targetId, metadata: { roles } })`.
A name-only edit is not audited (the plan scopes the audit row to the roles change).

# Task 3, part 1 — F-086: pending edits reach the creator and admins (DEC-53, DI-36)

Base: d510914 (05-14 Task 2). The plan names no separate evidence file for the F-086 protocol, so
it is recorded here with the other behaviour fixes of this plan.

## 7. The fix

GET /api/events/[id]: after the unchanged `transformEventFromDB`, a caller who is the row's
`created_by` or holds the admin role (`hasRole(ctx.profile, "admin")`) gets the transformed event
with `pending_edits: data.pending_edits` attached when the row has pending edits; when the row has
none, the creator and admins get the transformed event exactly as before (no new `null` key, so no
seeded row's bytes change). Everyone else gets the event with any `pending_edits` key removed, as
the PRESERVE suite's layer (b) requires even when a transform carries the column. The request
context from 05-10 is reused. `src/lib/tagMapping.ts` is unchanged, so the list routes are
unaffected.
