How to read "threw" and 500 rows. The fake has no upsert, ilike, contains or storage member. An
arm that reaches one of those throws: with an outer catch it answers 500, without one the
handler rejects and runArm() records "threw". Either way the caller got past every check the
arm makes first, so for this characterization it is an admission. The suites never pin a 500
or a throw as a PRESERVE value; the only exact bytes pinned are P1 (anonymous), P2 (banned on
the legacy arms) and P3 (onboarding/complete 200).

P1 derivation (anonymous rows below): 34 arms answer 401 {"error":"Unauthorized"}; events/[id]
PATCH answers 401 {"error":"You must be signed in to edit an event"}; events/create POST answers
401 {"error":"You must be signed in to create an event"}; recommendations/feedback POST answers
401 {"error":"Unauthorized. Must be logged in to submit feedback."}; feedback POST is admitted
with 200 {"success":true}; interactions POST is admitted with 201 {"success":true,…}. No
anonymous row on a non-tolerant arm made any database call (calls= empty).
