Why the mutation check ran after the fix commit: it restores with `git checkout --` and refuses to
start while a listed migration has uncommitted changes (05-11 learned this). The same holds for the
manual cycles below, which restore the committed file the same way.

Why manual cycles exist: the harness mutates CREATE POLICY statements only. Removing the re-created
own-row policy denies every self-update, which turns the ALLOW rows red (3, 12-15) but can never turn
a DENY row red. The F-006/F-007 denials come from REVOKE and GRANT statements, which the harness
cannot see, so M1 and M2 (the plan's two) remove the revokes that carry them. M3 (users INSERT) and
M4 (the C3 counter) were added to cover the two remaining behaviours of the file.

Why M2 does not turn the INSERT rows red: with the audit revoke removed, the two INSERT policies are
still dropped, so RLS (no INSERT policy) refuses the insert with the same SQLSTATE 42501. The INSERT
denial therefore has two independent barriers; 055 row 1 pins the policy half and row 2 the
privilege half, and M2 turned row 2 red.
