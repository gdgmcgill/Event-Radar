## 1. The fixes

src/lib/audit.ts: imports `getElevatedClient` from `@/server/db/elevated` instead of the service
factory; the `adminEmail` parameter and the `admin_email` key are gone from the insert; an
optional `requestId` is accepted; the insert's `{ error }` is read and a rejection is logged as
`console.error("[Audit] admin_audit_log insert rejected", { action, targetType, targetId,
requestId, code, message })`. The function still resolves without throwing.

Callers: all 15 `logAdminAction(` callsites in 11 route files (10 carried `adminEmail: user.email`
before; `admin/users/[id]` is new in Task 1) now pass `requestId: ctx.requestId` and no email.

src/app/moderation/page.tsx (server component): the audit read is the typed cookie client with
`select("id, admin_user_id, action, target_type, target_id, metadata, created_at")`; the
`(supabase as any)` cast, its eslint-disable line, the `as Promise<{ data: AuditEntry[] | null }>`
assertion and the local `AuditEntry` interface are deleted (F-072). A second read,
`users.select("id, name, email").in("id", <distinct admin_user_id>)` on the same cookie client,
builds the actor map; the actor renders as name, else the email's local part, else the first 8
characters of admin_user_id. `created_at` is `string | null` in the generated Row, so the
timestamp renders only when present.

src/app/moderation/audit-log/page.tsx (client component): rows still come from
`GET /api/admin/audit-log` (which selects `*`, the table's seven real columns; unchanged). After
each page arrives, the page reads `users.select("id, name, email").in("id", <distinct ids>)` on the
browser client (the same cookie session) and renders name, else email local part, else the first
8 characters of the id. The `admin_email` field is gone from its `AuditEntry`.
