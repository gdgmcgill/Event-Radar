## 1. What changed

New, under src/server/ratelimit/:
- types.ts: `RateDecision = { allowed, limit, resetAtMs }` and `interface RateLimitStore {
  consume(key, limit, windowMs): Promise<RateDecision> }`.
- policy.ts: `WINDOW_MS = 60_000`; `PUBLIC_BUDGETS = { GET: 300, mutation: 30,
  highFrequencyMutation: 300 }` (moved unchanged); `HIGH_FREQUENCY_POST_PREFIXES`;
  `ADMIN_PREFIX`; `ADMIN_BUDGETS = { GET: 600, mutation: 120 }` with DEC-50's rationale in the
  comment; `clientIp(req)` (x-real-ip, then the first x-forwarded-for hop, then "unknown");
  `rateLimitPolicy(req)` returning `{ key, limit, windowMs, scope }` or null outside /api/; and
  `tooManyRequests(limit, resetAtMs, nowMs)`, the existing 429 body and four headers.
- memoryStore.ts: the globalThis `__uni_verse_mw_rate_limit__` bucket map (same key), the same
  prune-then-fixed-window-from-first-hit counting as `consumeSync(key, limit, windowMs, nowMs)`,
  and `MemoryRateLimitStore` (its `consume` resolves `consumeSync` on a late-bound clock).
- index.ts: `applyRateLimit(req, store): Promise<NextResponse | null>` (policy, consume, 429 or
  null) and `getRateLimitStore()` returning one module-level MemoryRateLimitStore. 05-18 adds the
  distributed store's selection here and nowhere else.

Rewritten: src/middlewareRateLimit.ts. `applyApiRateLimit(req)` keeps its name, its synchronous
signature and its comment header. It returns null outside /api/ and for the admin scope, and
otherwise runs `rateLimitPolicy`, `consumeSync` and `tooManyRequests`. No budget literal remains in
the file.

src/proxy.ts: the first statements are now
    const rateLimitResponse = await applyRateLimit(request, getRateLimitStore());
    if (rateLimitResponse) return rateLimitResponse;
imported from "@/server/ratelimit". Nothing else in the proxy moved in this task.

## 2. Behaviour changes (INTENTIONAL BEHAVIOUR CHANGE in the commit body)

a) /api/admin/* is now rate limited: 600 GET and 120 non-GET per IP, per path, per 60 s, with the
   same 429 body and headers as the public budget. Before, the admin prefix was excluded.
b) The client address prefers x-real-ip over x-forwarded-for (research A5, DEC-50). Before,
   x-forwarded-for was read first. The two differ only when a request carries both and they
   disagree. Every PRESERVE suite sends x-forwarded-for alone and is unaffected.
Public budgets, the 429 body, every rate-limit header and the non-/api pass-through are unchanged
(equivalence test, §4).

The equivalence test freezes Date.now, runs the same table of eight requests (seven public /api
shapes plus one non-/api path) budget + 2 times through each path with distinct addresses, and
compares status, JSON body and all four headers on every call.

A defect found while writing it, fixed before the commit: the first MemoryRateLimitStore captured
the `Date.now` function reference as its default clock, so a spied clock never reached it. The
store now defaults to `() => Date.now()`, which reads the clock at call time.

## 9. The admin budget's input: /api GETs one moderation page load issues

Counted from the `fetch(` calls in src/app/moderation/**/page.tsx. A GET is a fetch without a
`method` option that runs on mount. The key is method:pathname:ip; the query string is not part
of it, so `?page=2` shares a bucket with page 1.

| Page | GETs on load | Distinct paths | Other fetches (mutations) |
|------|--------------|----------------|---------------------------|
| /moderation (dashboard) | 0 | 0 (server component; reads Supabase directly) | 0 |
| /moderation/pending | 0 | 0 (browser Supabase client read) | 7 |
| /moderation/users | 1 | /api/admin/users | 3 |
| /moderation/organizer-requests | 1 | /api/admin/organizer-requests | 1 |
| /moderation/audit-log | 1 (again per page turn) | /api/admin/audit-log | 0 |
| /moderation/clubs | 1 | /api/admin/clubs | 4 |
| /moderation/organizers | 1 | /api/admin/organizers | 2 |
| /moderation/events | 1 | /api/admin/events | 5 |
| /moderation/appeals | 2 | /api/admin/events, /api/admin/clubs | 2 |
| /moderation/featured | 1, then 1 per search | /api/admin/featured; /api/admin/events per search | 1 |
| /moderation/reports | 1 | /api/admin/reports | 1 |
| /moderation/stats | 3 | /api/admin/stats, /api/admin/analytics/users, /api/admin/analytics/events | 0 |

So a page load reaches any one admin path at most once. The widest page, /moderation/stats,
reaches three paths once each. The busiest single key in interactive use is GET /api/admin/events
from the featured picker's search-as-you-type. At 600 a minute (10 a second on one path), an
admin would have to reload one moderation page ten times a second for a minute to meet the
budget.

Admin mutations are keyed per path, and the paths carry the target id
(/api/admin/events/<id>/status), so each event, club or user has its own 120-a-minute bucket.
A moderator batch-approving a queue spends one hit per item, each against a different key. The
budget bounds a script hammering one target to two writes a second per address.
