Method (research § D, Pitfall 3):
  - Each probe is ONE psql invocation holding ONE transaction:
    BEGIN; SET LOCAL ROLE authenticated (or anon); set_config('request.jwt.claims', …, true) and
    set_config('request.jwt.claim.sub', …, true); SELECT auth.uid() proves the impersonation
    took; the statement; ROLLBACK.
  - One invocation per probe keeps psql's stderr (ERROR lines) attributable to its probe. A first
    single-invocation run printed the same outcomes but interleaved the two streams through the
    docker pipe.
  - No INSERT uses RETURNING, so an INSERT outcome is the WITH CHECK decision alone.
  - UPDATE/DELETE denials are silent 0-row outcomes. INSERT denials raise 42501.
  - Baseline and after counts are read as the session owner (bypasses RLS). They prove no probe
    persisted a row.
