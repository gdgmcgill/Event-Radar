<objective>
Deliver the classification slice end-to-end: every endpoint and every page moves from machine-derived signals to a resolved human verdict, every endpoint gains an explicit expected status for all thirteen personas, the derivation rules are written down, and the validator turns green.

Purpose: The signals are inputs to classification, not the classification. CERT-06 requires a generated persona-by-endpoint matrix that fails on any unclassified endpoint, so an unresolved field here becomes a failing Stage 4 gate. This is the task that makes the phase's third success criterion — a reviewer can answer these questions from the artifacts alone — actually true.
Output: fully classified `endpoints.json` and `pages.json`, a regenerated `endpoints.csv`, and `classification-rules.md`.
</objective>

    Write `.planning/audit/inventory/classification-rules.md` first, so the matrix is derived rather than asserted. At minimum: an anonymous caller against an authenticated route expects an unauthorized status; a permanently banned user expects a forbidden status on any route the ban check gates; a mid-onboarding user expects whatever the onboarding guard does, which is a redirect for pages and a specific status for routes; a cross-club attacker expects a forbidden status on any route scoped to a club they do not belong to and a success status elsewhere; a machine caller with no credential expects an unauthorized status on any machine route — which is exactly where the two confirmed fail-open handlers will show a divergence between expected and actual, and that divergence is the finding, so the expectation records what the route should return rather than what it does today; a non-McGill sign-in is not-applicable for endpoint rows because it is an authentication-flow case rather than an endpoint case.
