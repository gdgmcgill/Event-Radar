## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| audit tooling → `supabase/migrations/` | The directory under audit must not gain a file produced by the audit |
| production database → captured diff | Diff output can carry function bodies and grants |
| generated types file → trust | The types file is evidence under suspicion, not a source of truth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08-01 | Tampering | `supabase/migrations/` gaining a generated migration | mitigate | The migration-writing flag is forbidden; stdout redirection is used instead; an acceptance criterion asserts the migration count equals the Wave 1 baseline and `git status -- supabase/` is empty |
| T-01-08-02 | Tampering | Production or staging schema mutated by a push or repair | mitigate | Push, repair, and reset-against-linked are on the phase forbidden list; only history-read and diff commands are invoked |
| T-01-08-03 | Information Disclosure | Captured diff output carrying a connection string or a function body with an inline key | mitigate | Diffs are scoped to the public schema; the task sweeps its own artifacts for JWT, secret-prefix, connection-string, and bearer shapes and scrubs before completing |
| T-01-08-04 | Spoofing | Trusting the types file as schema truth and missing real drift | mitigate | Production truth comes from the column census only; the types file is parsed as the third column to be judged, and the generator-output finding is recorded explicitly |
| T-01-08-05 | Repudiation | A drift table that silently omits a table its parser could not read | mitigate | The validator asserts every table in the census has at least one drift row, so a parser hole fails the check rather than passing quietly |
| T-01-08-SC | Tampering | npm/npx package installs | accept | Only the already-installed Supabase CLI and Node built-ins are used; no registry fetch, and the guard's lockfile hash check runs in both task verifies |
</threat_model>
