    The probe is header-only and read-only: issue GET requests with the headers-only flag, never a mutating method, and capture only the status line plus the cache-state, matched-path, cache-control, CDN-cache-control, vary, age, set-cookie, and request-id headers. Write one file per route, session, and iteration under `.planning/audit/cache/curl/`, naming files from a slugified route plus the session label plus the iteration number.

    Sampling matters as much as the request. Repeat each route-and-session pair at least three times, interleaving the two sessions and spacing requests so all iterations for a route fall inside one shared-cache freshness window. A cross-session hit can only appear on the second session's request, and a burst of requests inside one window is the sample most likely to miss an intermittent leak — the session-refresh middleware emits a set-cookie header only on requests where it actually refreshes, and a response carrying set-cookie is not cacheable, so the steady-state request is the cacheable one.

    Write `.planning/audit/cache/curl-summary.json` with a top-level object carrying a `control` field and a `requests` array. Each request object records route, session label, iteration, status, cache state, age value, whether a set-cookie header was present, and the cache-control value observed. The control result is a first-class top-level field, not just another row. If the control never returns a hit across the whole run, the harness is broken and no conclusion about personalized routes is licensed — record that explicitly as the run's headline and treat the run as inconclusive rather than clean.

    Do not expect a cache-reason header from this probe; it is internal to the platform and not returned to clients. Capture the request id so a reason can be retrieved from platform logs later if a specific request needs one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| one user's session → another user's response | The shared CDN is the channel under test |
| live session token → committed evidence | The probe holds real tokens and writes files that get committed |
| audit tooling → production application state | Any non-GET request would mutate real user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12-01 | Information Disclosure | Personalized JSON served from a shared CDN to a different user | mitigate | The two-session interleaved probe measures it directly; a cross-session hit is recorded as leak-confirmed and becomes a Critical finding routed to REFAC-19 |
| T-01-12-02 | Information Disclosure | A live session token committed inside a captured set-cookie line | mitigate | Captures are header-only; set-cookie values are replaced with a marker inside the writing pipeline; acceptance criteria negative-grep the whole cache directory for the session-cookie name prefix and JWT shapes |
| T-01-12-03 | Information Disclosure | Cookie values written into a file under the planning directory | mitigate | Cookies live only in shell environment variables; the checkpoint instructions forbid pasting them anywhere; the Task 3 sweep asserts absence |
| T-01-12-04 | Tampering | A probe request mutating production data | mitigate | GET only; an acceptance criterion asserts no mutating verb appears in the script; headers-only requests do not send a body |
| T-01-12-05 | Spoofing | A run with no hits mistaken for an all-clear | mitigate | A positive control is a first-class field; when the control never hits, every personalized row is forced to not-probed and the run is recorded inconclusive |
| T-01-12-06 | Information Disclosure | A database password or token echoed by shell command tracing | mitigate | Command tracing is forbidden in the script and asserted absent by an acceptance criterion |
| T-01-12-SC | Tampering | npm/npx package installs | accept | The probe uses the system HTTP client and Node built-ins only; no package manager is invoked |
