    CLI contract: `--check <name>` runs exactly one named check and exits non-zero if it fails or if its input artifacts are absent; bare invocation runs all 21 checks and requires every one to pass; `--quick` runs only the checks whose input artifacts already exist and reports the rest as `SKIP`; `--selftest` asserts that every name in the check registry has a function, that the three schema files parse, and that the hand-rolled schema checker correctly accepts a valid fixture and rejects an invalid one, without touching any evidence artifact. Output is one line per rule in the form `PASS|FAIL|SKIP <check-name> :: <rule> :: <detail>` so a failure names the exact rule, mirroring the repo's Jest reporting granularity. Exit code is 0 only when no rule reported FAIL.

    Register exactly these 21 check names, implementing the assertions written in RESEARCH § Validation Architecture Test Map: `schema-snapshots`, `drift`, `endpoints`, `endpoints-signals`, `pages`, `rls`, `heatmap`, `service-role`, `cache`, `authz-registers`, `cron`, `deps`, `baseline`, `observability`, `dead-code`, `bundle-sweep`, `threat-models`, `storage`, `dates`, `findings`, `sla`.

    Hard rules the implementation must encode. Expected row counts are parsed from `.planning/audit/baseline/versions.txt` keys `route_ts_count`, `page_tsx_count`, and `migration_count` — no numeric literal for these counts may appear in `validate.mjs`. The `endpoints` check requires zero residual placeholder sentinels in any human-classification field; a missing key is a schema error, not an implicit placeholder. The `endpoints-signals` check is the weaker gate used before hand classification: schema-valid, correct row count, and `signals` present on every row, with placeholders still permitted. The `pages` check additionally asserts the cross-reference invariant that every route appearing in `inventory/build-routes.txt` is present in `inventory/endpoints.json`, `inventory/pages.json`, or `inventory/special-files.json`. The `service-role` check asserts the register row count equals the count of `endpoints.json` rows whose `signals.uses_service_client` is true plus the two non-route callsites, and that all four justification answers are non-null on every row. The `cache` check asserts every endpoint row with `personalized` true has a `cache/cache-matrix.csv` row whose verdict is not the not-probed sentinel, and that the positive-control row exists and records at least one cache HIT. The `findings` check asserts ids are unique and match `^F-\d{3}$`, every finding carries all ten required fields, every Critical and High has at least one `affected_paths` entry with line numbers, every `evidence` value resolves to an existing path under `.planning/audit/`, no `evidence` value is an inline literal, any `risk_acceptance` whose `expiry` is in the past forces status back to Open, and the `FOUNDATION_AUDIT.md` finding count equals `findings.json` length. Errors are caught at the top level and reported with `process.exit(1)`; never print a caught error object that could embed a credential — print the rule name and a scrubbed message.
