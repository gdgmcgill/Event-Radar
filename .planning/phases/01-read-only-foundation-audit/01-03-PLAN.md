## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server code → client bundle | Any secret crossing this boundary is shipped to every visitor |
| build process → working tree | A build that rewrites a tracked config file would break the phase's exit criterion |
| sweep output → git history | The sweep artifact is committed; a captured match would publish the secret it found |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Information Disclosure | Client bundle carrying a service-role key or admin allowlist | mitigate | Task 3 sweeps six named patterns plus the literal value and a JWT shape; a non-zero count becomes a Critical finding candidate |
| T-01-03-02 | Information Disclosure | The sweep artifact itself echoing a matched secret | mitigate | Report file names and counts only; no flag that prints matching content; acceptance criteria negative-grep the artifact for JWT and connection-string shapes |
| T-01-03-03 | Spoofing | A clean sweep result that proves nothing because the build env had no secret | mitigate | `ENVSTATE` is determined by an exit-code probe that never prints the value and is recorded as the artifact's first line; absence yields INCONCLUSIVE, not clean |
| T-01-03-04 | Tampering | `npm run build` mutating `tsconfig.json`, `next-env.d.ts`, or the lockfile | mitigate | `readonly-guard.sh` runs immediately after the build in Task 1's verify; `tsconfig.json` is already in its normalized form and the generated files are gitignored |
| T-01-03-05 | Elevation of Privilege | Pages reported unguarded because only the middleware ring was checked | mitigate | `layout_guard` resolves the nearest guarded ancestor; acceptance criteria require at least 14 pages to resolve to one |
| T-01-03-SC | Tampering | npm/npx package installs | accept | `npm run build` runs the already-installed tree; no install, no `npx` fetch; the lockfile hash check in the guard detects any npm-initiated repair |
</threat_model>
