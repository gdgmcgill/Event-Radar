## 1. The stand-in (e2e/helpers/sharedCacheProxy.ts)

- `startSharedCacheProxy(upstream)` -> `{ url, stats(), close() }`; a Node `http` server on 127.0.0.1,
  port 0. Node built-ins only (node:http, node:net types): no dependency was added, package.json and
  package-lock.json are untouched.
- Stores a response only when every Vercel rule holds: GET/HEAD; no Authorization on the request; 200 or
  404; no Set-Cookie; the governing directive (Vercel-CDN-Cache-Control, else CDN-Cache-Control, else
  Cache-Control) names no private/no-cache/no-store and has s-maxage > 0 (max-age counts on the two
  CDN-specific headers only); Vary names neither Cookie nor *. Key: `METHOD URL`, never the cookie.
  Expiry honours the shared lifetime; stale-while-revalidate is not modelled (stated in the file).
- Answers `x-sim-cache: HIT|MISS|BYPASS`; a HIT is served from memory without contacting the origin
  (`stats().upstream` is asserted unchanged across the HIT).
- Bodies live in memory only and are cleared by close(); no fs write, no console call in the file:
  $ grep -n "writeFile\|appendFile\|createWriteStream\|console\." e2e/helpers/sharedCacheProxy.ts
  exit=1 (no match)
- Persona cookies: the storage states are host-only cookies for 127.0.0.1 (auth.setup.ts adds them with
  url http://127.0.0.1:3000), and a cookie's domain match ignores the port, so the stand-in listens on
  127.0.0.1 rather than `localhost` (which would carry no cookie). Recorded as a deviation from the plan's
  "on localhost" wording.
