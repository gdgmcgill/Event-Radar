What this proves: with withSentryConfig wrapping next.config.js, next build succeeds with NO Sentry
credential at all. The Phase 5 CI-env command (05-04 build-ci-env.txt) is reused and extended: every
SENTRY_* variable and NEXT_PUBLIC_SENTRY_DSN is set to the EMPTY string, not unset, because @next/env
never overrides an already-defined variable (research C8), so no local .env file can supply one.
CI=true reproduces CI's non-silent plugin output; SENTRYCLI_SKIP_DOWNLOAD=1 matches ci.yml.
sourcemaps.disable is !SENTRY_AUTH_TOKEN, so nothing is uploaded; the plugin reports it will not
create a release, which is the expected warning.
