# ===========================================================================
# DRIFT vs THE PHASE 1 BASELINE — recorded, not reconciled away
#
# 02-04-PLAN.md task 1 asserts that next_static_bytes here must EQUAL the
# next_static_bytes in .planning/audit/baseline/versions.txt. It does not:
#
#   .planning/audit/baseline/versions.txt   next_static_bytes=4490961  (2026-09-14T07:25:05Z)
#   this file                               next_static_bytes=4491132  (2026-09-15T04:46:57Z)
#   delta                                   +171 bytes  (+0.0038%)
#
# The expectation is NOT lowered and the number is NOT adjusted to match. What
# follows is what was established about the delta, each line re-runnable.
#
# 1. The two byte-count commands are equivalent. The Phase 1 figure used a macOS
#    stat format flag; this file uses the portable pipeline. Run on the SAME build
#    tree they return the same integer, so the delta is not a measurement artifact:
#      find .next/static -type f -exec stat -f%z {} + | awk '{s+=$1} END{print s}'   # -> 4491132
#      find .next/static -type f -print0 | xargs -0 cat | wc -c                       # -> 4491132
#
# 2. The build is deterministic within a run-to-run comparison. Two independent
#    cold builds (rm -rf .next && npm run build) on this tree produced byte-identical
#    output: next_static_bytes 4491132 both times, first_load_js_sum 39846495 both
#    times, /docs 1964234 both times. The delta is not build noise.
#
# 3. The delta is localised to ONE SHARED CHUNK. It is uniformly +171 bytes on
#    EVERY route, not concentrated anywhere:
#      /docs   1964063 -> 1964234   (+171)
#      /help    840048 ->  840219   (+171)
#      sum    39838971 -> 39846495  (+7524 = 44 routes x 171)
#    A chunk in every route's first-load set grew by 171 bytes; nothing else moved.
#
# 4. No committed build input that Next reads changed. Everything altered between
#    the baseline commit and HEAD (git diff --stat 1e2647e^ HEAD -- . ':!.planning'):
#      package.json      scripts (check:feedback -> test/test:ci), engines, @types/node major
#      package-lock.json @types/node only (12 insertions / 34 deletions)
#      tsconfig.json     removed the now-deleted vitest.config.ts from `exclude`
#      .github/workflows/ci.yml, .nvmrc, .gitignore   CI and tooling only
#      src/middleware.test.ts, src/middlewareRateLimit.test.ts   new test files, outside
#                        the App Router bundling graph and excluded by tsconfig
#      vitest.config.ts, vitest.setup.ts, test-results/   deleted residue
#    None of these is a client-bundle input. No runtime production dependency
#    resolved to a different version.
#
# 5. Two candidate causes remain, both outside what this plan may touch:
#    (a) .env.local. Next inlines NEXT_PUBLIC_* values into a shared client chunk.
#        The file is uncommitted and phase-locked constraint 3 forbids reading it,
#        so this cannot be confirmed here. It is the single most likely cause: a
#        value edited between 2026-09-14 and 2026-09-15 would shift one shared
#        chunk by a fixed amount and every route by that same amount, which is
#        exactly the shape of observation 3.
#    (b) browserslist date sensitivity. The build emits a caniuse-lite staleness
#        warning, and the `not dead` term in browserslist's `defaults` query is
#        evaluated against the CURRENT DATE rather than static data. A browser
#        crossing that boundary between the two capture dates changes the
#        transpile target set and therefore shared-chunk bytes.
#
