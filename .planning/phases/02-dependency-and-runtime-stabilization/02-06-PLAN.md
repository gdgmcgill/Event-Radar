<objective>
Batch 3: rename the file that is this application's only page-level authentication ring, atomically, with nothing else in the commit.

`src/middleware.ts` carries the rate limiter, the Supabase session refresh, the eight-entry protected-route redirect, the ban check, and the onboarding guard. Next 16 deprecated the `middleware` file convention in favour of `proxy`, and it **hard-throws at build time if both files exist** — so there is no incremental path, no create-verify-then-delete, and no halfway state to inspect. It is one commit.

Purpose: This is the single highest-risk change in Phase 2 and the only one that touches the request path. If the rename silently disables the ring, every protected page becomes public and nothing in the dependency batches would have caught it. The mitigation is not caution, it is measurement: two characterization suites written in plan 02-02 already pass against the pre-rename code, and the smoke script's protected-route rows already pass against the pre-rename app. This batch records both, performs the rename with the official codemod, and records both again.
Output: `src/proxy.ts`, `src/proxy.test.ts`, the before/after captures, the rename diff, and the STAB-06 migration note with its honest coverage limitation.

**No CONTEXT.md exists for this phase** — there are no `D-NN` user decisions. Locked constraints come from `.planning/PROJECT.md` § Constraints, `.planning/REQUIREMENTS.md` § Out of Scope, and `02-RESEARCH.md` § Phase Constraints.
</objective>

- **Do not rename the `[Middleware]` log prefix** in the catch block to `[Proxy]`. It is the project's logging convention (see `.claude/CLAUDE.md` § Logging) and changing it is a behaviour-visible diff inside the one commit that must read as a rename. Change it later in its own commit or leave it.
- **Do not rename `src/middlewareRateLimit.ts`.** The relative import survives the rename unchanged, nothing forces the rename, it adds diff noise, and REFAC-18 rewrites that module onto a distributed store in Phase 5 anyway.

Do not attribute runtime behaviour to this rename either. Proxy defaults to the Node.js runtime rather than the Edge runtime, but that change landed when this project moved to Next 16 — the *rename* changes nothing further about the runtime.
