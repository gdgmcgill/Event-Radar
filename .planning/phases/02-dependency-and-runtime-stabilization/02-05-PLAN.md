Batch 2: move the framework, alone, in one commit.

Exactly one of the 24 High/Critical production packages is genuinely reachable on every request, and it is `next`. This batch upgrades `next` and its lockstep `eslint-config-next`, touches nothing else, and adds one source comment to the config line that is silently load-bearing for security.

**The requirement text is stale and the plan says so rather than diverging silently.** STAB-05 names "the patched release closing the July-2026 CVE batch", which is 16.2.11. The August 2026 security release superseded it: two criticals were disclosed — an unauthenticated RCE via AVIF in the Image Optimization API, and an unauthenticated RCE on Windows-hosted servers — patched only at **16.3.3**. `npm audit` on this tree reports the vulnerable range as everything up to and including 16.3.2. The research target is **16.3.5**, which stays inside the declared `^16.0.3` range and keeps the React peer at `^18.2.0 || ^19.0.0`. That target is re-verified against the live registry at the start of this batch, because the research document's own validity window is short and Next ships security releases monthly.

Purpose: Batch 1 shrank the tree so this batch's lockfile diff is small enough to actually read. This upgrade closes the phase's only Critical rooted in reachable code and, as a side effect, pins `postcss` and `sharp` forward, closing three more nested rows.
Output: `next` and `eslint-config-next` on the verified target, a commented `next.config.js`, the STAB-05 upgrade note, and the batch-2 gate evidence.
