Decision: the plugin IS registered (@typescript-eslint/eslint-plugin@8.47.0,
brought by eslint-config-next — nothing installed, lockfile untouched). The
boundary therefore moved from core `no-restricted-imports` to
`@typescript-eslint/no-restricted-imports` with `allowTypeImports: true` on
both pattern groups (the option is per pattern group). The source excerpt shows
what the option exempts: an ImportDeclaration with importKind 'type', or one
whose every specifier is an inline `type` specifier; the same logic applies to
`export … from`. ExportAllDeclaration (`export * from`) is always reported.
The allow-list block now turns `@typescript-eslint/no-restricted-imports` off.
The fallback branch — core rule plus an explicit ignores entry for the two
type-only importers — was NOT needed. The core rule was never configured
anywhere else (0 restricted rules before), so nothing was overwritten.
