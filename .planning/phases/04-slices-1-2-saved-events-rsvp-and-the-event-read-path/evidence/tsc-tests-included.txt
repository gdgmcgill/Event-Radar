[2 · the fixes, by class — every one inside a test file]

A. Cross-file collisions (TS2451 26, TS2393 12, and the 1 TS2353).
   Seven suites were scripts, not modules, so their top-level `mockUser`,
   `mockSupabase`, `GET`, `createMockQueryBuilder` ... shared one global scope.
   Each became a module: rsvp, clubs/analytics, events/analytics and
   date-validation by the `import { NextRequest } from "next/server"` each now
   needs anyway; reviews (whose handlers take a plain Request, so it needs no
   import) by an `export {}` with a one-line comment naming DI-24.

   The date-validation TS2353 ("'email' does not exist in type '{ id: string }'",
   line 100) was a collision artefact, not a fixture lie: the file's own
   `mockUser` is declared `{ id: string; email: string } | null`, but in the
   shared script scope the checker resolved the name to another suite's
   `{ id: string }` declaration. It disappeared with module-ification and no
   fixture changed. The research had counted it among "three genuine fixture
   lies"; the other two were friends-defect's, already fixed in 04-05.

B. Handler references (TS2554 14 in rsvp and reviews, TS2352 7 across rsvp,
   reviews, both analytics suites and date-validation).
   Each `let GET: any` / hand-written `(req: Request) => Promise<Response>`
   became the handler's own type, `(typeof import("<route>"))["GET"]`, and the
   `as typeof GET` casts on assignment were dropped because the assignment now
   type-checks on its own. Requests are built as the handler declares them:
     - rsvp, events/analytics, clubs/analytics, date-validation (create POST and
       [id] PATCH): NextRequest, as those handlers declare `NextRequest`.
       rsvp's JSON-body-invalid case also builds a NextRequest now.
     - reviews: plain Request, because reviews/route.ts declares
       `(request: Request, context: RouteContext)`.
   Contexts were already `{ params: Promise.resolve({ id }) }`; none changed.
   rsvp's createMockRequest writes the init inline (Next's RequestInit forbids
   `signal: null`, which the DOM RequestInit type allows) — same method,
   headers and body.

C. get-events (TS2352 8): `let capturedBuilder: B | null = null` is narrowed
   to `null` at the use site because the assignment happens in a closure, so
   `capturedBuilder as B` read as a null-to-B conversion. Declared as
   `let capturedBuilder = null as B | null` so the declared type survives; the
   eight `as B` reads now narrow `B | null` to `B`. No assertion changed.

D. audit-shape (TS2554 3): `ModerationDashboardPage({} as any)` became
   `ModerationDashboardPage()` — the page is declared with no parameters
   (src/app/moderation/page.tsx:36). Three `any`s removed, none added.

Nothing needed a change under src/app, src/lib or src/server; no error was
stopped on and recorded as source-only.
