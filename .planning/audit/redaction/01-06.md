## 1. How credentials were handled

The plan's Task 1 checkpoint asked the operator for `SUPABASE_ACCESS_TOKEN`, `PROD_PROJECT_REF`,
`STAGING_PROJECT_REF`, or the `SUPABASE_DB_PASSWORD` / `PROD_DB_URL` fallback. **None of those
was ever supplied.** The operator resolved the gate by a different route: authenticating the
**Supabase MCP server** (Management API) in the orchestrator session.

That changes the redaction surface in a way worth stating precisely:

| | Planned path | Path actually used |
|---|---|---|
| Credential material | personal access token, or a Postgres URI with a password | an OAuth grant held by the agent runtime |
| Where it lived | the executing shell's environment | outside the repository entirely |
| Could it reach a file? | yes, if echoed, traced, or passed as a CLI argument | no — it was never in the shell |
| Could it reach a log? | yes, via shell tracing or an error object | no |

**No credential value entered this machine's shell environment during this plan, so there was no
value available to leak into an artifact.** That is a stronger guarantee than scrubbing, and it is
the reason every count in §4 is zero.

The practices the plan mandates were nonetheless honoured and are recorded here because they
govern the *next* pass, when a connection string may well exist:

- **Environment variables only, never CLI arguments.** No secret was passed as an argument to any
  command. The canonical dump command recorded in `schema/prod.schema.sql`,
  `schema/staging.schema.sql`, and `schema/local.schema.sql` is written as
  `supabase db dump --db-url "$PROD_DB_URL" ...` — the variable is dereferenced by the shell, and
  the literal never appears in an argument vector, in shell history, or in a captured log.
- **No shell command tracing.** `set -x` appears in no script this plan wrote, and
  `tools/readonly-guard.sh` carries an explicit comment explaining why it must never be enabled:
  the guard runs in the same phase as credentialed tasks and tracing would echo the environment.
- **The audited credential is never the transport.** `tools/sql-readonly.mjs` contains zero
  references to `createServiceClient` or `SUPABASE_SERVICE_ROLE_KEY`. The service-role key is the
  RLS-bypassing credential this phase exists to audit; using it to perform the audit would be
  circular and it enforces nothing.
- **Errors are scrubbed before they are printed.** `tools/sql-readonly.mjs` carries a redaction
  table (line 80 and neighbours) that rewrites a JWT, an `sb_secret_`-prefixed key, and a
  password-bearing `postgres://` URI to placeholders before any error body reaches stdout. A
  caught error object is never printed raw, because an HTTP client's error frequently embeds the
  request it failed on, including its `Authorization` header.
- **`.mcp.json`.** Authenticating the MCP server wrote one untracked file outside `.planning/`:
  `.mcp.json`. It was swept before anything else was done and contains a server name, a transport
  type, and the public `https://mcp.supabase.com/mcp` endpoint — **no credential**. It is recorded
  as an expected untracked entry in `baseline/BASELINE-REFRESH.md` and is **not committed** by
  this phase.

## 2. What was excluded, per artifact

"Excluded" here means *never captured in the first place*, which is the only exclusion that is
safe once `commit_docs` is `true` and the artifact is in git history permanently.

| Artifact | Excluded / scrubbed | Why |
|---|---|---|
| `schema/prod.schema.sql` | the **auth schema**, entirely | An auth dump can carry role grants and inline keys into git history permanently. The snapshot is scoped to `public` (all objects), `storage` (buckets and policies only), and `cron` (the job inventory only). The canonical dump command recorded in the file's header carries the same scoping as `--schema public,storage`; the auth schema is never named in it. |
| `schema/prod.schema.sql` | auth schema **columns, grants, and data** | The only auth observation retained anywhere in this plan is a bare list of 23 table *names* in `raw/prod/auth-config-tables.json`. No auth column, no auth grant, no auth row was captured. |
| `schema/prod.schema.sql` | a **roles-only dump** | Never produced and never written to a committed path. `--role-only` is on the phase's forbidden list. |
| `schema/prod.schema.sql` | the **project reference** | The header prints `<PROD-PROJECT-REF>`, the placeholder the capture agent substituted at capture time. The literal ref appears in no committed file. |
| `raw/prod/*.json` (21 files) | nothing — **0 redactions at capture** | `MANIFEST.json` reports `total_redactions: 0` across all 20 captures. Independently re-verified here (§4); the claim is not taken on trust. |
| `raw/prod/MANIFEST.json` | the **project reference** | Stored as `<PROD-PROJECT-REF>`. The human-readable project *name* (`universe-events`) is retained deliberately: it is not a credential and it is what makes the provenance auditable. |
| `schema/staging.schema.sql` | n/a — a deferred-with-reason stub | No staging database was contacted, so there was nothing to redact. The stub names the blocking variable **NAMES** only (`STAGING_PROJECT_REF`, `STAGING_DB_URL`), never values. |
| `schema/local.schema.sql`, `schema/local-reset.txt` | n/a — local-only | The local reset targets a containerised database on `localhost` with the CLI's default local credentials, which are public constants, not secrets. The transcript was still swept. |
| `tools/sql-readonly.mjs`, `tools/sql-readonly-pg.mjs` | n/a — no values, by construction | Both read credentials from the environment at runtime. Neither contains a credential, and neither writes one to stdout or to a file. `sql-readonly-pg.mjs` additionally documents that its `pg` dependency installs to a scratch prefix **outside** the repository so `package.json` and `package-lock.json` stay byte-identical. |
| `tools/gen-prod-schema.mjs` | n/a — reads no environment variable | The generator opens no database connection and reads no environment variable, so it cannot leak one. |

## 3. What the plan expected to redact and did not have to

Recorded so the difference is legible at the phase gate rather than read as an omission:

- **A password-bearing connection string.** None existed. `supabase db dump` was never run against
  a remote project, because no `--db-url` was available.
- **A personal access token in a request header.** No `Authorization: Bearer` header was ever
  constructed by this machine. `tools/sql-readonly.mjs` was **built** but not **run** against
  production — the MCP transport was used instead. Recording that honestly matters: the script is
  the documented path for a later pass, not the path that produced these artifacts.
- **Session cookies.** Not applicable to this plan; the `set-cookie` and `Cookie:` captures belong
  to AUDIT-08 in a later plan.

Pattern 6b is wider than `REDACTION.md` requires. The ledger's pattern 6 reads both project refs
from the environment at sweep time, but neither `PROD_PROJECT_REF` nor `STAGING_PROJECT_REF` was
ever exported in this session, so that pattern could not be instantiated. Sweeping for the
*shape* of a Supabase project ref — any bare 20-character lowercase token — is the substitute, and
it is strictly more sensitive than the literal it replaces. It returned zero.

### The three non-zero counts, itemised and dismissed

`REDACTION.md`'s self-reference caveat says a file containing the *patterns* will match them. All
three hits are exactly that, verified by reading each one in context:

| File | Line | Match | Verdict |
|---|---|---|---|
| `tools/sql-readonly.mjs` | 80 | `[/sb_secret_[A-Za-z0-9_-]+/g, '<REDACTED-SECRET-KEY>']` | A scrubbing **rule** in the transport's own redaction table — the code whose job is to remove secret keys from error output. Not a value. |
| `baseline/BASELINE-REFRESH.md` | 13 | `sb_secret_` | Prose listing which patterns `.mcp.json` was swept for. Not a value. |
| `baseline/BASELINE-REFRESH.md` | 13 | `sb_publishable_` | Same sentence, same prose list. Not a value. |

**This document is itself a fourth such file** and will match patterns 1–7 at the phase gate, for
the same reason. Plan 01-13 should treat hits in `REDACTION.md`, `redaction/*.md`, and `tools/`
as expected pattern definitions and verify by eye, as `REDACTION.md` instructs. Every other hit
anywhere under `.planning/audit/` is a leak until proven otherwise.
