## 4. Remaining local limitations and decisions

- **DI-61 remains partial.** Store configuration validation, required-distributed fail-closed behavior and address-free logging have been improved. Budgets still use method + full pathname + client address; varying target paths avoids a shared actor/scope budget. `x-real-ip`, then the first `x-forwarded-for` value, are trusted without an application-enforced trusted-proxy boundary. `ADMIN_PREFIX` remains `/api/admin` with prefix matching. Document or change those semantics and prove the deployment ingress behavior before calling DI-61 closed.
- **Redis runtime failures remain fail-open.** The distributed store deliberately allows requests on timeout/error; requiring a configured distributed store does not turn a later Redis outage into fail-closed limiting. This is a stated availability policy, not proof of abuse resistance during an outage.
- **The signed webhook has no timestamp window (DI-78).** HMAC authenticity and content-hash duplicate rejection do not establish signature freshness. Changing this requires the producer's signing contract and an owner decision.
- **CSP still includes `unsafe-inline` (DI-80 / F-055).** A nonce policy is not delivered by the current static CSP. Sentry v11's explicit data-collection baseline (DI-79) also remains a separate dependency decision; current scrubbing is not that upgrade.
- **Upload checks inspect file signatures, not complete image decoding.** Matching image magic bytes does not prove that the full file decodes safely or contains only image content. Malformed multipart requests now intentionally return contracted 400 responses rather than uncaught 500s; this is a deliberate defect correction, not unchanged response behavior.
- **Storage delivery/configuration is not proven by metadata pgTAP.** Policy tests cover ownership; verify remote bucket existence, public-read intent, allowed MIME types, size limits and real Storage API uploads on the target environment. Database policy tests alone cannot prove bucket configuration or blob behavior.
- **The literal CERT-18 fallback promise is unresolved.** Popularity reads use Supabase too. Returning a private, observable failure when that database is unreachable avoids falsely cached empty success, but does not satisfy an offline popularity fallback. Implement and test a bounded alternate source or explicitly revise/accept that requirement through the foundation process.
- **Invitation resend remains a known limitation.** No decline operation exists in the current product/schema. Expired invitations remain pending, so the pending-invitation duplicate guard can prevent a replacement; expiry refusal is tested, resend is not claimed working.
- **Dates retain DEC-80 semantics.** Stored values encode Eastern wall clock with a Z suffix; this work does not reinterpret historical rows as instants. See [time semantics](../../../docs/discovery-time-semantics.md) before changing database timezone extraction.
- **Privacy/product carryovers require explicit disposition.** DI-75's profile-header/admin identity presentation and other owner-owned behavior choices must be reconciled against the updated product direction. They are not silently accepted by this report. McGill rejection remains intentional until M1.
- **No accepted-risk signatures were obtained.** A limitation listed here is disclosed, not accepted. Use the existing finding register and dated owner approval where the foundation process allows acceptance.
